🗄️ Database & ETL Operations (Tier 1 Architecture)
This directory contains the infrastructure required to spin up the Collections Data Warehouse, define the Star Schema, and execute the ETL (Extract, Transform, Load) pipeline.

By containerizing the database, this project ensures a reproducible, isolated environment that mimics a production banking ecosystem.

🏗️ Architecture Overview
Database Engine: PostgreSQL 15 (via Docker)

Schema Design: Star Schema (1 Fact Table centralizing Interactions/Payments, linked to Dimensions)

ETL Tooling: Python (pandas, SQLAlchemy)

Management Interface: pgAdmin 4 / DBeaver

🚀 Quick Start: Spinning up the Database
We use Docker Compose to instantly deploy a pre-configured PostgreSQL instance and a pgAdmin web interface.

Prerequisites
Docker Desktop installed and running.

Step 1: Start the Containers
Open your terminal, navigate to the root of the project, and run:

Bash
# Start the database and pgAdmin in detached mode
docker-compose up -d
Step 2: Verify the Containers
Bash
docker ps
You should see two containers running: collections_db (Port 5432) and pgadmin (Port 5050).

🔗 Connecting to the Database
You can interact with the database using any standard SQL client.

Option A: Using DBeaver / DataGrip (Recommended)

🛠️ The ETL Pipeline (Loading the Data)
Once the database is running, you need to populate it with the raw data generated by the Python scripts.

1. Initialize the Star Schema
Before loading data, we must create the relational tables (Dimensions and Facts).

Method: Execute the 01_create_tables.sql script located in the init/ folder against the collections_dw database.

(Note: If configured in your docker-compose.yml, this script may run automatically on the first startup).

2. Execute the Python ETL Load
Ensure you have generated the raw data first (see 01_data_sources/README.md). Then, run the ETL script to clean, transform, and load the data into PostgreSQL.

Bash
# Navigate to the ETL folder and run the loader
cd 03_etl
python load_data.py
What this script does:

Reads the raw CSV files generated in Step 1.

Performs data type casting (e.g., converting strings to standard DATETIME formats).

Utilizes SQLAlchemy to execute bulk inserts into the Dimension and Fact tables.

🧠 Business Logic Views (The "Golden Record")
Once the data is loaded, run the scripts located in the queries/ folder to build the analytical views used by Power BI and Excel.

attribution_logic.sql: Solves the core business problem of matching "orphan" digital payments to agent interactions within a 3-day window using Window Functions.

kpi_calculations.sql: Defines the logic for Capped KP and Utilization Alignment at the database level, ensuring a single source of truth before data hits the visualization layer.

🧹 Teardown
When you are finished working, you can spin down the containers to free up system resources.

Bash
# Stop and remove the containers
docker-compose down

# (Optional) Wipe the database completely to start fresh
docker-compose down -v
