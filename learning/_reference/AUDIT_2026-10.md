# Learning Lab Audit — October 2026

**Scope:** `learning/` (6 tracks, 16 modules, 111 tasks)
**Auditor:** MIS & Analytics review
**Mode:** Static audit + targeted fixes. Docker/PostgreSQL was **not running**, and Power BI Desktop / LibreOffice were **not launched**. No KPI-parity query, DAX execution, workbook render, or VBA run was performed. This is a documentation and contract audit; live-number validation remains outstanding.

## 1. Executive summary

The lab is structurally strong: every module has both `tasks.md` and `results.md`, every track has a README, and the tasks follow the workplace-inbox pattern. The main weaknesses were **contract drift** (tasks and results disagreeing), **fabricated targets** (a 45% RPC goal that does not exist), **undefined variables in worked solutions**, and **work artifacts committed to git** despite the README promising they are private.

## 2. Method

1. Read every `tasks.md` and `results.md` across 16 modules, plus the six track READMEs.
2. Cross-checked task lists against result sections; every file pair matched (9/8/9, 6/6/5, 5/5/4, 9/13/7, 6/6/5, 8).
3. Validated KPI definitions against `database/migrations/002_kpi_views.sql` and `004_agents_scorecards.sql`.
4. Validated goals against `Dim_Targets` in `dashboards/dax/collections_dax_v2.csv` and `dashboards/dax/dax_targets_and_comparisons.md`.
5. Checked Python snippets with `compile(..., "exec")` after de-indenting; no syntax errors remain in the edited files.
6. Grepped for every known drift marker (`45%`, `0.45`, `payment_count`, `parents[2]`, `DATA_SHEET = "Data"`, `shared`, `A1:H`, `five metrics`).

**Project targets used throughout:**

| KPI | Goal | Amber floor (0.85 × goal) |
|---|---|---|
| PTP% | 80% | 68% |
| KP% | 80% | 68% |
| ACW RPC | 120 s | inverted (direction LowerIsBetter) |
| ACW Non-RPC | 25 s | inverted |

| Cures / THT | 2.4 | 2.04 |

There is **no RPC% target** in the project. Every task that invented one was rewritten.

Definitions used: `PTP% = ptp_count / rpc_count`; `KP% = kept_count / (kept_count + broken_count)` with `Pending` excluded. `v_daily_mis` exposes `kept_count`, `broken_count`, `kept_pct`, `ptp_count`, `ptp_pct`, but **not** `payment_count`.

## 3. Findings fixed

### 3.1 Excel — payment count contract (Basic)

`v_daily_mis` has no `payment_count`, yet Basic Task 8 asked learners to export five metrics including payments, and Task 9 reconciled five numbers. The contract now says: export `v_daily_mis` **and join `fact_payments`** at `(payment_date, agent_id)` grain. Task 9's reconciliation SQL uses two CTEs (`mis`, `pay`) and passes the date twice.

Files: `learning/excel/basic/tasks.md`, `learning/excel/basic/results.md`.

A second Basic drift was fixed at the same time: Task 3 placed the lookup demo on `Daily!I5` / `J5`, but the `Daily` sheet has no agent columns. It now points at `AgentDaily!C5` / `D5`. Task 4's pivot filter referenced a `Month` field that did not exist on `AgentDaily`; `Month` is now column `G` in both the manual task and the openpyxl generator, and the pivot range is `A4:G`.

### 3.2 Excel — KP% consistency (Medium and Advanced)

The medium workbook had an RPC%-only summary and RAG. It now carries `Kept` and `Broken` on `Data`, computes `KP%` in `Summary!H`, applies RAG to `H5:H16` with amber `0.68` and green `0.80`, moves the MoM delta to column `I`, moves the demo agent lookup from `J/K` to `L/M`, and extends print ranges to `A1:I16` / `A1:J`. The automation task and results were updated in lockstep.

The advanced pack had the same gap. It now includes `Kept`/`Broken`, a nine-column Summary (`Month … KP % … Promises Δ`), `Parameters!E2:E3 = 0.68/0.80`, RAG on `H`, and the VBA constant `DATA_SHEET = "Daily"` (it was `"Data"`, which did not exist). The generator normalizes friendly CSV headers (`Date, Agent ID, …`) to snake_case before validation, so the same file feeds both pandas and the QueryTable refresh.

One additional false claim was corrected while editing: Medium's fallback said `dim_employees` is SCD2 and needs `is_current = TRUE` to de-duplicate. It is not — `dim_employees` is one row per agent; history lives in `dim_employee_history`. The filter remains as a guard, but the warning now says joining the history table would duplicate the six transferred agents.

Files: `learning/excel/medium/{tasks,results}.md`, `learning/excel/advanced/{tasks,results}.md`.

### 3.3 Notebooks — medium defects

- The assertion in Task 1 counted `data_sources/raw/shared` as a month folder. It now excludes `shared` in both the loader and the assertion.
- Task 2 used a fabricated `TARGET = 45.0` RPC line. It now charts **monthly KP%** against the **80% goal**, with points coloured green/amber/red at `80%` and `0.85 × 80% = 68%`.
- Task 3 used `pay` and `ptp` without loading them; Task 5 used `emps` without loading it. Explicit `load_year(...)` / `read_csv(...)` cells were added.

Files: `learning/notebooks/medium/{tasks,results}.md`.

### 3.4 Python — path and promise parity

- Medium Task 4's script lives at `learning/python/medium/work/reconcile.py`, so `parents[2]` resolved to `learning/python/`, not the project root. Fixed to `parents[4]`.
- Advanced `promise_kpis()` computed `is_kept_math` but grouped by `status`, so the computation was dead code and the advertised "installment-aware" output was just status counts. It now excludes `Pending`, evaluates `Kept ÷ (Kept + Broken)` at plan level, and returns `plans_kept_math` / `plans_broken_math`.

Files: `learning/python/medium/results.md`, `learning/python/advanced/results.md`.

### 3.5 Power BI — fabricated targets and wrong RAG bands

- Task 2 invented a 45% RPC target and used measure names (`[PTP %]`, `[KP %]`) that do not exist in the model. It now uses the project schema (`MetricName`, `GoalValue`, `AmberThreshold`), real measures (`[Promise Rate]`, `[KP Rate]`), and the 80% goals.
- Task 3 used 0.80/0.60 for KP and 0.45/0.35 for RPC. RPC colouring was removed; KP/PTP colours now read goal and amber bounds from `Dim_Targets`, yielding 0.80 green and 0.68 amber.

Files: `learning/powerbi/medium/{tasks,results}.md`.

### 3.6 SQL — false premises and an unfinished query

- Basic Task 1 claimed facts "dwarf every dim except `dim_calendar`". False: `fact_writeoffs` (~441) and `fact_recoveries` (~323) are smaller than `dim_clients` (10,000) and `dim_accounts` (~15,480). The text now says table type comes from grain, not row count.
- Advanced Task 4 left the composite-score comparison as a commented sketch. It is now a complete `normalized` + `scored` query that applies the 004 weights and returns both aggregation variants plus their gaps.
- Advanced Task 9 said "six collectors switched teams". The generator can move an agent to a different supervisor **inside the same team**, so the claimed six *team* movers is not guaranteed. The task now says "up to six changed supervisor"; the query reports supervisor and team attribution separately and tells the learner why June may show fewer than six team-level rows.

Files: `learning/sql/basic/results.md`, `learning/sql/advanced/{tasks,results}.md`.

## 4. Residual risks (not fixed)

1. **No live validation.** The following claims are static-only:
   - SQL/KPI parity (`v_daily_mis`, `v_agent_scorecards`, `v_dpd_migration_matrix`).
   - DAX measure names and behavior in the actual PBIX.
   - openpyxl formulas rendering correctly in LibreOffice/Excel.
   - VBA `RefreshPack` refreshing a table without breaking structured references.
2. **VBA QueryTable growth.** The `RefreshPack` macro clears `A5:L` and refreshes into `A4`. The Excel Table (`tblDaily`) does not automatically resize when the CSV has more rows than the current table. A production version should resize the `ListObject` after refresh. This is now documented implicitly by the header contract, but not coded.
3. **Excel CSV header contract.** The generator normalizes headers, but the VBA QueryTable writes the CSV header row into `A4`. If the CSV headers are not the friendly table names, structured references break. The results now say the header row must match the table headers; a stricter fix would stage the CSV on a hidden sheet.
4. **Committed learner artifacts.** They are untracked in the index but still present locally; `git status` shows staged deletions until the next commit. This is intentional per the no-commit instruction.
5. **Excel Medium `parents[2]` is correct** because the script lives in `work/scripts/`. The Python Medium `parents[4]` is correct because that script lives directly in `work/`. Do not "normalize" these blindly.
6. **Reference copies may drift.** `learning/_reference/` is a self-contained copy by design. Any future change to the project targets or view definitions must be mirrored there explicitly.
