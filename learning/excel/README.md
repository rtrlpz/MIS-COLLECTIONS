Notebooks explain numbers; **Excel ships them**. The daily MIS sheet, the month-end pack, the file a supervisor opens, reads and prints — in most companies that file is a workbook. This track teaches you to *engineer* workbooks from Python: clean layouts, live formulas, traffic-light formatting, print setup. This is the exact skill behind this project's planned Phase 10 (`reports/generate_daily_mis.py`).

## At work, you reach for Python-to-Excel when…

- Ops needs the same report every morning — you script it once and regenerate it forever.
- A stakeholder won't open a notebook or query a database, but will absolutely open Excel.
- Month-end demands a pack: cover sheet, tables, charts, checks.
- Someone prints your report and it should look professional on paper, not like a database dump.

## Two tools, one rule

| Tool | What it does |
|---|---|
| `pandas.to_excel` | Gets numbers onto sheets fast (one call) |
| `openpyxl` API | Makes it a *report*: styles, merged titles, formulas, freeze panes, print areas, charts |

> Rule of thumb: **pandas writes the numbers, openpyxl makes the document.** A raw `to_excel` dump is a draft, never a deliverable.

Two habits this project cares about:

- **Live vs pasted:** a cell with `=B2/C2` updates when inputs change; a pasted number is frozen forever. Decide per cell — reports want a few live cells (totals, rates), not ten thousand volatile formulas.
- **The audit habit:** anything exported must agree with the official SQL view (`v_daily_mis`). If it doesn't, that's a finding to explain — not something to eyeball away.

## Setup

1. `conda activate mis-collections`
2. One dependency: `pip install openpyxl`, then verify with `import openpyxl`.
3. Scripts and `.xlsx` outputs go under `learning/excel/<level>/work/`. Raw CSVs stay read-only.

## What each level covers

| Level | You master | Typical deliverable |
|---|---|---|
| `basic/` | Workbook anatomy: sheets, headers, styles, pandas→Excel, page setup | A clean single-sheet table worth printing |
| `medium/` | The daily MIS: multiple sheets, live formulas, red/yellow/green flags, freeze panes, print areas | The morning report, generated by script |
| `advanced/` | Period-end pack: cover/dashboard sheet, charts, built-in validations, audit vs the SQL view | A workbook finance could sign off |

## How the files work

Each level folder has:

- `tasks.md` — your inbox: workplace requests with Done-When checklists (no code, no expected numbers)
- `results.md` — full worked solutions: complete openpyxl scripts AND VBA modules; open **only after** attempting, then run/rebuild yourself
- `work/` — your scripts and `.xlsx` files; git-ignored scratchpad

Routine: read task → attempt in `work/` → **open the workbook in Excel/LibreOffice and look at it as a reader** → then compare with `results.md`. A spreadsheet you never opened is an untested claim.

## Move up when…

- **basic → medium:** you can produce a styled, readable sheet from a DataFrame without notes.
- **medium → advanced:** you know per cell whether it should be live or pasted — and why.
- **done:** you can hand over a multi-sheet pack whose numbers match the database and prove it.
